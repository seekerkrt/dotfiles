# Handoff Inline

現在のセッション内容を引き継ぎ形式のMarkdownレポートに整理し、最終回答として直接返す。

このSkillは、一時的にコピーして使うためのレポートを作る。レポートをファイルとして永続化してはならない。

## 書き込み禁止契約

- ファイルやディレクトリを作成・更新・改名・移動・削除しない。
- `~/handoff/` その他のhandoff保存先へ書き込まない。
- 一時レポート、ログ、パッチ、トランスクリプトなどのファイルを作成しない。
- `git add`、`git commit`、`git push` その他のリポジトリ書き込み操作を実行しない。
- working tree、index、branch、stash、remote、GitHub上の状態を変更しない。
- handoffファイルを作成したと主張したり、存在しない出力パスを提示したりしない。

レポートを正確にするために必要な場合のみ、次のようなread-onlyコマンドを使用してよい。

- `pwd`
- `git status --short --branch`
- `git diff --stat`
- `git diff --check`
- `git log -1 --oneline`
- 既存ファイル、差分、ログ、テスト結果を確認するコマンド

レポートを埋めるためだけに、新しい実装、広範な調査、高コストな検証を始めない。現在のセッションに実在する作業と証拠だけを報告する。重要な事実が不明な場合は、不明または未確認と明記する。

## 出力契約

- 完結したMarkdownレポートを、最終回答ひとつとして返す。
- レポート本文から始め、外側に前置き・説明・追記を加えない。
- レポート全体をコードフェンスで囲まない。
- Codexの`/copy`ですぐ利用できる形にする。
- repository path、branch、HEAD、変更ファイル、実行コマンド、結果、判断、残作業などの具体的事実を保持する。
- 確認済みの事実と推測を分ける。推測を確認済みとして書かない。
- 価値の低い会話履歴や、重複した経過説明を含めない。
- ユーザーが別言語を明示しない限り、日本語で出力する。

## 推奨構成

必要な節だけを使い、空の節は省略する。

```markdown
# Inline handoff: <repository / Issue / task>

## Repository

- Repo: `<path または name>`
- Branch: `<branch>`
- HEAD: `<sha>`
- Agent: `<agent>`

## 依頼内容

<依頼された内容、対象scope、重要な非scope制約。>

## 確認したファイル

- `<path>`

## 変更したファイル

- `<path>`

repositoryファイルを変更していない場合は、その旨を明記する。

## 完了した作業

<確認済みの実施内容、調査結果、判断、実装結果。>

## 検証

- Command: `<command>`
- Result: `<result>`

完了、失敗、skip、未実行を区別する。

## 現在の状態

<working tree、staged / unstaged、branch / HEAD、runtime stateなど、安全に再開するために必要な情報。>

## 残作業

<未解決事項、risk、follow-up scope、または最小の次の一手。>

## 注意事項

<重要な制約、保持すべきユーザー変更、忘れてはいけない事実。>
```

## 品質基準

別のAgentやChatGPTがセッション全体を読み直さなくても、何が起きたかを理解し、安全に作業を継続できる内容にする。同時に、チャットへ直接貼り付けられる程度に簡潔に保つ。
